# alfa-hack-2026

Новостная аналитика для принятия бизнес-решений. Контур: React/Nginx → Go API → PostgreSQL/Redis; задачи анализа через транзакционный outbox попадают в Kafka → отдельный Go analysis worker. Отдельный Go news worker собирает новости.

## Быстрый запуск без ключей

```sh
docker compose -f compose.p1.yaml up --build
```

Откройте `http://localhost:5173`. Если порт занят локальным Vite, задайте `FRONTEND_PORT=5174` в `.env` и откройте `http://localhost:5174`. `http://localhost:<FRONTEND_PORT>/healthz` проверяет Go API через Nginx. Порт 8080 наружу не опубликован.

По умолчанию `DEMO_SEED=true`: в ленте появляется отдельная вымышленная компания U001 и три демонстрационные новости. Результат явно помечен `go-worker-demo` и содержит шаблонный текст. Это позволяет проверить интерфейс и очередь до появления ключей; это **не** настоящий новостной анализ.

В этой рабочей папке создан локальный `.env`, который указывает importer на три обезличенных CSV из `docs`: профили компаний, связи с физическими лицами, агрегированные входящие/исходящие платежи. Файлы разделены `;`; платёжный CSV содержит около 1,38 млн строк и читается потоком. Импорт компаний выполняется пачками и повторно пропускается при неизменных SHA-256. Конфликтующий ID U_428697 встречается в исходном CSV с разными профилями; importer исключает неоднозначные ID и пишет их количество в лог. UI показывает ограниченную выборку и поиск по ID, отрасли или региону. В чистом клоне без `.env` используются отслеживаемые учебные CSV из `company_news_pipeline/data/mock`; банковские PDF и выданные CSV в Git не добавляются.

## Реальный контур

1. В локальном `.env` поставьте `DEMO_SEED=false` и убедитесь, что `DATASET_KIND=anonymized` и пути указывают на выданные CSV из `docs`. В чистом клоне сначала скопируйте `.env.example` в `.env` и положите файлы в `docs`. Добавьте `SERPER_API_KEY`, `LLM_API_KEY`, точное имя разрешённой ТЗ модели в `LLM_MODEL` и адрес совместимого API. `LLM_RESERVED_RUB_PER_CALL` — проверенная по тарифу провайдера верхняя стоимость одного вызова; без неё анализ не выполняется. Суммарный дневной лимит в БД не более 500 ₽.
2. Для извлечения банковских PDF из `docs` включите профиль `research`: `docker compose -f compose.p1.yaml --profile research up --build`. Отдельный Python контейнер извлекает страницы; для страниц без текстового слоя использует Tesseract OCR. JSONL сохраняется в Docker volume, Go importer загружает фрагменты и ссылки на документы в PostgreSQL. Повторный запуск использует кэш при неизменных SHA-256. Первый OCR всех PDF может занять несколько минут.
3. News worker запрашивает Serper каждые 6 часов и сохраняет только публикации с датой и URL; дубли по компании и каноническому URL объединяются. По умолчанию опрашиваются первые 20 компаний из выборки. Для другого набора задайте `NEWS_COMPANY_IDS=U_67,U_76` в `.env`. Для обезличенных компаний поиск ведётся по отрасли и региону, а не по вымышленному имени.
4. В интерфейсе выберите компанию и новость, задайте вопрос. Analysis worker строит план, учитывает профиль и аналоги, выбирает материалы банка, составляет ответ, проверяет обязательные поля и источники, выполняет отдельную критическую проверку, при ошибке делает ограниченную попытку исправления. В UI выводятся позиция банка, вывод модели, действия, источники, этапы и форма оценки. Агрегированные показатели задач, новостей и оценок доступны в `GET /api/quality`.

Данные и ключи проверьте по логам:
`docker compose -f compose.p1.yaml logs importer research-exporter research-importer news-worker worker api`.

## Устойчивость и проверка

Go API записывает задание и outbox одной транзакцией; диспетчер отправляет его в Kafka. Worker делает до трёх попыток с задержкой; окончательная ошибка идёт в `analysis.failed`, а причина видна в API и UI. Повторная доставка завершённого задания не создаёт новый результат. Оператор может повторно отправить задачу:
`docker compose -f compose.p1.yaml run --rm -e ANALYSIS_ID=<id> api -mode retry-job`.

```sh
go test ./backend
npm ci
npm run lint
npm run build
docker compose -f compose.p1.yaml config
# После установки ключей и завершения OCR/импорта:
python scripts/smoke.py
```

В Windows Go/npm могут падать на UNC пути `\wsl.localhost\...`; команды разработки запускайте из WSL по Linux пути. В Docker запуск идёт через Compose.

## Границы текущего решения

Без ключей работает только явно помеченный demo сценарий. Новости пока отбираются по отрасли/региону; полный текст первоисточника не извлекается и не проверяется автоматически. Связи и платежи передаются в анализ агрегатами. UI является демонстрационным входом, не интеграцией в настоящий Альфа-Бизнес. Авторизации для настоящих клиентских данных нет: используйте только обезличенный набор. Лимит LLM опирается на заданную верхнюю стоимость вызова; перед демонстрацией проверьте фактический тариф и ответ провайдера о модели. OCR и импорт выданных PDF проверены в Compose: 177 фрагментов из 9 документов. Сквозной запуск с ключами пока не подтверждён.
