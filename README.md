**Новостная аналитика для принятия бизнес-решений.**
Контур: React/Nginx → Go API → PostgreSQL/Redis; задачи анализа через транзакционный outbox попадают в Kafka → отдельный Go analysis worker. Отдельный Go news worker собирает новости.

## Быстрый запуск без ключей

```sh
docker compose -f compose.p1.yaml up --build
```

Откройте `http://localhost:5173`. Если порт занят локальным Vite, задайте `FRONTEND_PORT=5174` в `.env` и откройте `http://localhost:5174`. `http://localhost:<FRONTEND_PORT>/healthz` проверяет Go API через Nginx. Порт 8080 наружу не опубликован.

По умолчанию `DEMO_SEED=true`: в ленте появляется отдельная вымышленная компания U001 и три демонстрационные новости. Результат явно помечен `go-worker-demo` и содержит шаблонный текст. Это позволяет проверить интерфейс и очередь до появления ключей; это **не** настоящий новостной анализ.

В этой рабочей папке создан локальный `.env`, который указывает importer на три обезличенных CSV из `docs`: профили компаний, связи с физическими лицами, агрегированные входящие/исходящие платежи. Файлы разделены `;`; платёжный CSV содержит около 1,38 млн строк и читается потоком. Импорт компаний выполняется пачками и повторно пропускается при неизменных SHA-256. Конфликтующий ID U_428697 встречается в исходном CSV с разными профилями; importer исключает неоднозначные ID и пишет их количество в лог. UI показывает ограниченную выборку и поиск по ID, отрасли или региону. В чистом клоне без `.env` используются отслеживаемые учебные CSV из `company_news_pipeline/data/mock`; банковские PDF и выданные CSV в Git не добавляются.

## Реальный контур

1. В локальном `.env` поставьте `DEMO_SEED=false` и убедитесь, что `DATASET_KIND=anonymized` и пути указывают на выданные CSV из `docs`. В чистом клоне сначала скопируйте `.env.example` в `.env` и положите файлы в `docs`. Добавьте `SERPER_API_KEY`, `LLM_API_KEY`; используйте RouterAI base URL `https://routerai.ru/api/v1` и модельный alias `~z-ai/glm-flash-latest` из runbook. Go worker использует стандартную сетевую маршрутизацию хоста для `https://routerai.ru/api/v1`. В запрос отправляется `max_tokens=32000`; приложение не ограничивает число запросов или расходы на LLM.
2. Для извлечения банковских PDF из `docs` включите профиль `research`: `docker compose -f compose.p1.yaml --profile research up --build`. Отдельный Python контейнер извлекает страницы; для страниц без текстового слоя использует Tesseract OCR. JSONL сохраняется в Docker volume, Go importer загружает фрагменты и ссылки на документы в PostgreSQL. Повторный запуск использует кэш при неизменных SHA-256. Первый OCR всех PDF может занять несколько минут.
3. News worker запрашивает Serper отдельно за 7 и 90 дней каждые 6 часов и сохраняет только публикации с датой и URL; дубли по компании и каноническому URL объединяются. Общие отраслевые запросы в одном проходе выполняются один раз для нескольких компаний. По умолчанию опрашиваются первые 20 компаний из выборки. Для другого набора задайте `NEWS_COMPANY_IDS=U_67,U_76` в `.env`. Для обезличенных компаний это подборка отраслевых новостей, а не прямые упоминания компаний. Поиск ведётся по широкой отраслевой теме, а не по вымышленному имени.
4. В интерфейсе выберите компанию и новость, задайте вопрос. Analysis worker передаёт в один запрос RouterAI профиль, аналоги, новость, вопрос и банковские выдержки; получает JSON заданной структуры и локально проверяет обязательные поля и ID источников. Прежний экспертный многовызовный workflow сохранён в коде, но отключён. В UI выводятся позиция банка, вывод модели, действия, источники, этапы и форма оценки. Агрегированные показатели задач, новостей и оценок доступны в `GET /api/quality`.

Данные и ключи проверьте по логам:
`docker compose -f compose.p1.yaml logs importer research-exporter research-importer news-worker worker api`.

## Компании с загруженными новостями

Снимок на 26 октября 2026 года: для первых 20 обезличенных компаний сохранено **211** новостей за последние 90 дней, из них **100** — за последние 7 дней. У каждой из 20 есть хотя бы одна новость в обоих окнах:

- U_1, U_10, U_1000, U_100000, U_100001
- U_100009, U_100013, U_100017, U_10002, U_100023
- U_100024, U_100025, U_100031, U_100033, U_100035
- U_10004, U_100043, U_100044, U_10005, U_100059

Это **отраслевые** публикации, найденные Serper по профилю ОКВЭД, а не подтверждённые упоминания конкретной компании: идентификаторы клиентов обезличены. В `news_items` хранится заголовок, краткий фрагмент, URL источника и дата публикации. Полный текст статьи не извлекается. Числа меняются при обновлении воркера каждые 6 часов; список выше — проверенный снимок, а не гарантия неизменного количества.

Для просмотра текущих количеств по компаниям:

```sh
docker compose -f compose.p1.yaml exec -T postgres psql -U alfa -d alfa -c "SELECT company_id, count(*) FILTER (WHERE (payload->>'published_at')::timestamptz >= now()-interval '7 days') AS week, count(*) AS ninety FROM news_items WHERE company_id <> 'U001' AND (payload->>'published_at')::timestamptz >= now()-interval '90 days' GROUP BY company_id ORDER BY company_id"
```
## Проверка заглушек и неполных данных

- В текущем локальном `.env` установлен `DEMO_SEED=false`: вымышленная U001 скрыта из API компаний и новостей, а её исторические записи исключены из метрик качества. Сами старые записи U001 остаются в PostgreSQL, чтобы не удалять данные автоматически. При `DEMO_SEED=true` включается явно помеченный шаблонный сценарий U001.
- Три CSV в `docs` и девять банковских PDF используются активным Go-контуром; в PostgreSQL загружены 85 513 обезличенных профилей и 177 фрагментов банковских документов. Если `.env` отсутствует, Compose использует учебные CSV из `company_news_pipeline/data/mock`; UI помечает такие профили как учебные.
- Новости для перечисленных 20 компаний получены от Serper, содержат дату и URL. `Text` — краткий фрагмент ответа поставщика; поле `fullText` для реальных новостей не заполняется. Полный текст статьи и подтверждение прямого упоминания компании пока не собираются. Подборка по отрасли может содержать нерелевантные публикации; её нужно оценивать по источнику до принятия решения.
- Активный путь анализа — Go worker и разрешённая LLM через RouterAI. Шаблонный ответ используется только для U001 в деморежиме. Go worker отправляет `max_tokens=32000` и `reasoning.effort=low` через обычную сетевую конфигурацию; таймаут запроса — 50 секунд. Экспертный многовызовный путь отключён и оставлен в коде. Внутренних лимитов частоты запросов и бюджета LLM нет.
- Неиспользуемый Python/Flask/AG2 runtime удалён. В `company_news_pipeline/` оставлены fallback mock CSV, документы и планы; Python/Flask/AG2 runtime удалён. Manifest источников для OCR находится в `research/sources.json`. `docs/llm-response-example.json` — пример формата ответа, не источник данных приложения.
- Интеграция с реальным Альфа-Бизнесом и авторизация для настоящих клиентских данных пока отсутствуют; текущий UI предназначен для обезличенного набора ТЗ.
## Устойчивость и проверка

Go API записывает задание и outbox одной транзакцией; диспетчер отправляет его в Kafka. Worker делает до трёх попыток с задержкой; окончательная ошибка идёт в `analysis.failed`, а причина видна в API и UI. Повторная доставка завершённого задания не создаёт новый результат. Оператор может повторно отправить задачу:
`docker compose -f compose.p1.yaml run --rm -e ANALYSIS_ID=<id> api -mode retry-job`.

```sh
go test ./backend
npm ci
npm run lint
npm run build
docker compose -f compose.p1.yaml config
# После установки ключей и завершения OCR/импорта:
python scripts/smoke.py
```

В Windows Go/npm могут падать на UNC пути `\wsl.localhost\...`; команды разработки запускайте из WSL по Linux пути. В Docker запуск идёт через Compose.

## Границы текущего решения

Без ключей работает только явно помеченный demo сценарий. Новости пока отбираются по отрасли/региону; полный текст первоисточника не извлекается и не проверяется автоматически. Связи и платежи передаются в анализ агрегатами. UI является демонстрационным входом, не интеграцией в настоящий Альфа-Бизнес. Авторизации для настоящих клиентских данных нет: используйте только обезличенный набор. Лимит LLM опирается на заданную верхнюю стоимость вызова; перед демонстрацией проверьте фактический тариф и ответ провайдера о модели. OCR и импорт выданных PDF проверены в Compose: 177 фрагментов из 9 документов. Сквозной запуск с ключами пока не подтверждён.
